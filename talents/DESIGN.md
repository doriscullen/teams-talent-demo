# iCode Talents 演示 Demo 设计（v2）

- **目的**：给客户讲清楚两类用户的使用旅程：管理员生产、审阅并发布知识；开发者更新并应用知识。
- **形态**：独立启动的本机服务加 React + TypeScript + Ant Design 页面，外壳（侧栏、顶栏、主题）与 iCode Teams 一致。团队、成员、项目、代码仓、设计文档和共享会话读取自 iCode Teams 导出的快照；Talents 自己的数据是 mock，保存在本机状态文件中；已发布的知识写入共享数据目录供 Teams 读取（见 README）。不改动 iCode 配置。
- **页面原则**：
  - 尽量简洁，只呈现用户需要操作或需要知道的内容，不展示系统内部规则。可能有用的细节收进“查看详情”。
  - 不用“A · B · C”把多个短语拼在一起。需要并列多项信息时，用带标签的字段（如“输入：1 个代码仓”）。
  - 每张卡片只保留用户做决定要用的两三项信息，其余放进详情。

## 1. 产品形态

```
开发者端（本机） ── 共享会话 ──▶ 团队空间（云端） ◀── 发布知识 ── 管理员端（本机）
      ▲                                │                          │
      └──────── 更新 / 应用知识 ────────┘           本机 iCode 挖掘知识、审阅发布
```

- **两种客户端入口**：管理员端和开发者端，都运行在用户本机，调用本机的 iCode。
- **团队空间（云端）**：保存已发布的知识，以及团队成员共享的会话。
- **管理员端**：在本机登记来源（本地代码仓、文档集），从团队空间获取成员共享的会话，用本机 iCode 运行知识能力，审阅产物后发布到团队空间；会话轨迹诊断的优化建议逐条应用到项目 Skill 或 AGENTS.md 规则。
- **开发者端**：查看已加入项目中已发布的知识，一键应用到本机 iCode，有新版本时更新；可以用 CodeGraph、文档 RAG 检索为本地代码仓和文档建立索引。会话共享在 iCode Teams 中设置，不在 Talents 中。
- **Demo 中的模拟**：顶栏右侧提供“管理员端 / 开发者端”切换，模拟两台电脑上的两个入口；两边共用一份数据，管理员发布后，开发者端立即可见。

## 2. 角色与可见范围

- **团队**：成员和项目都来自 iCode Teams（团队“信用卡研发团队”，项目“信用卡营销交付”）。
- **管理员**（Teams Owner，林悦）：挖掘、审阅、发布知识；只能看到本团队成员共享的会话。
- **开发者**（Teams 成员，陈晨）：只应用知识，只能看到已加入的项目中已发布的知识，以及团队知识。会话共享在 iCode Teams 中设置。
- **团队级与项目级**：来源、知识任务和产物都属于团队或某一个项目。项目级的来源是 Teams 项目的代码仓、设计文档，以及在项目中登记的本地文档；团队级的来源是在团队中登记的本地文档，例如行内规范。任务只能使用同一层级的来源，产物也归这一层级。团队知识在每个项目中都可用。
- 管理员自己要用知识时，切换到开发者入口即可。

## 3. 演示脚本

**管理员端**
1. **项目**：进入项目，在“来源”页签看代码仓、文档集，以及文档集的版本记录。
2. **知识能力**：按四类介绍能力。
3. **知识任务**（项目的页签）：历史中有一条已完成的“会话轨迹诊断”。演示不新建诊断任务。
4. **产物管理**（项目的页签）：
   - 打开“信用卡营销返现业务知识”的新版本，与线上版本对比后发布。
   - 打开会话轨迹诊断（卡片提示“3 条优化建议待应用”），看诊断报告，再逐条查看建议：应用 Skill 建议（写入 arch-adr-writing 1.1.0）和任务指令建议（加入 AGENTS.md 规则），工具调用建议暂不采纳。

**开发者端**（切换入口）

5. **项目知识**：看到刚发布的知识，预览后一键应用；对“有更新”的知识点更新，看到管理员写的更新说明。
6. **本地索引**：为本地代码仓建立代码索引并应用。

## 4. 管理员端页面

导航：团队、项目（下面列出各个项目）、知识能力。团队和项目是同级的两个层级，结构与 iCode Teams 的“项目 / 项目名 + 顶部页签”一致。

### 4.1 团队与项目
- **项目列表**（`#/projects`）：项目卡片，字段是名称、说明，以及“代码仓”“文档集”两个字段列出来源名称；有待审阅的产物时，右上角显示“N 个待审阅”。项目来自 iCode Teams，不在 Talents 中新建。
- **项目**（`#/projects?project=…&tab=…`）：标题是项目名和说明，右上角“在 iCode Teams 中管理”。下面是页签：产物管理（默认打开，有待审阅的产物或待应用的建议时显示数量）、知识任务、来源。页签右侧是当前页签的操作：新建任务、登记本地文档来源。
- **团队**（`#/team?tab=…`）：与项目相同的三个页签，标题下说明“团队知识在每个项目中都可用”。
- 面包屑：项目 / 信用卡营销交付；打开产物时为 项目 / 信用卡营销交付 / 产物名，团队为 团队 / 产物名。
- iCode Teams 链接到 `#/review?project=…`、`#/tasks?project=…`，打开对应项目的页签。

### 4.2 来源
- **项目的来源**：分“代码仓”“文档集”“会话与 Skill”三组列出卡片。不设“全部来源”视图。
- **会话与 Skill**（来自 iCode Teams，只读）：两张卡片。“成员共享的会话”显示会话数、成员数、最近更新；“项目 Skill”显示数量和其中几个名称（即 Teams 项目概览中的“项目可用 Skill”）。点卡片打开右侧抽屉：搜索加分页列表（每页 10 条）；点一行，在同一抽屉中切换到详情（会话显示元数据，不显示原文；Skill 显示 SKILL.md），顶部“返回”。
- **团队的来源**：只有在团队中登记的本地文档目录（团队没有代码仓）。
- **来源卡片**：图标、名称、路径、说明；代码仓另有“分支”，文档集另有“文件：23 个，来自 Git 仓库”“最近变化”。
- **登记来源**（右侧抽屉）：类型 → 目录（读取后显示概览，文档集显示来自 Git 仓库还是共享目录）→ 名称、说明（可选）。来源归入当前所在的团队或项目，一个来源只属于一个层级。
- **文档放在哪里**：Talents 不托管文档，只登记位置（Git 仓库或共享目录）。新增、修改、删除文档都在原位置进行，页面上不提供上传、编辑、删除文档的入口。
- **来源详情**（右侧抽屉）：
  - 代码仓：路径、远端、当前分支、最近提交、所属。
  - 文档集：说明、路径、来自（Git 远端和分支，或共享目录）、文件数、最近检查（附“检查更新”）、所属；版本记录；文件表格（文件名、所在目录、更新时间，最新版本中新增或修改的文件标“新”“改”），默认显示 10 行，其余可以展开。
  - 顶部“编辑”：修改名称和说明。
  - 不显示产出状态，产出归产物管理管。
  - 底部操作：移除来源、新建知识任务（来源已预选）。
- **文档版本**（与 Talents 的“来源版本”一致）：
  - 来源检查对比文件清单和内容摘要，发现变化才记录一个版本；没有变化不记录。检查发生在每天定时、任务运行前和手动“检查更新”时。
  - 版本用发现变化的那次检查的时间标识，例如“10-25 14:20 版本”，不用 vN，避免和知识的版本混淆。一天内可以有多个版本，不合并，每个版本关联当时的原文快照，便于回查出处。
  - 版本记录按时间倒序列出每个版本的新增、修改、删除。
- **会话和 Skill 的管理**在 iCode Teams 中进行；Talents 只展示，并在“会话轨迹诊断”中使用。
- **下拉框**：全站使用 Ant Design 的下拉，成员等长列表带搜索。

### 4.3 知识能力
按四类分组，每组标题下有一句说明：

| 分类 | 说明 | 能力 |
|---|---|---|
| 知识索引 | 快速找到相关的代码和文档 | CodeGraph、文档 RAG 检索 |
| 文档知识提取 | 从需求、设计文档中提取业务知识 | 业务知识提取 |
| 代码知识挖掘 | 从 PR 和代码变更中反推开发范式与业务规则 | 开发范式挖掘（PR）、开发范式挖掘（代码片段） |
| 轨迹分析 | 从 Agent 会话中找出问题和改进点 | 会话轨迹诊断 |

- **能力卡片**：名称、一句话说明、“输入”“产出”“更新”三个带标签的字段，以及一个操作“新建任务”。从这里新建的任务需要在表单中选择属于团队还是哪个项目，创建后进入那个层级的知识任务页签。
- **构建与更新**（对应 Talents 引擎声明中的 `build` / `update`）：每个能力都能构建；能否更新由能力声明。更新时 Talents 把“和上次比变了什么”交给能力。

| 能力 | 构建 | 更新 |
|---|---|---|
| CodeGraph | `codegraph init` 建立代码图谱 | `codegraph sync`，只同步上次构建以来的代码变化 |
| 文档 RAG 检索 | 切分文档，建立 BM25 + 向量混合索引 | 只处理新增和修改的文档，移除已删除文档的片段 |
| 业务知识提取 | 读取全部文档并提取 | 根据文档变化（新增、修改、删除的文件和上一版产物）修订受影响的知识 |
| 开发范式挖掘（PR / 代码片段） | 每次归档新的范式并重建 `index.md` | 不支持 |
| 会话轨迹诊断 | 分析所选会话（只能选 Teams 已归集原文的会话），生成诊断报告和优化建议 | 不支持，每次运行生成新的诊断 |

### 4.4 知识任务
- **列表**：只列出当前层级的任务。两个页签加一排能力筛选（全部 / 知识索引 / 文档知识提取 / 代码知识挖掘 / 轨迹分析），两个页签共用这排筛选。
  - **当前任务**：运行中和等待运行的任务（定时任务、尚未到点的预约），运行中的排在最前。卡片字段：来源、时间、下次运行、最近运行及产出；运行中显示进度。
  - **历史**：已运行完的一次性任务，按运行时间倒序排列。卡片字段：来源、运行于、产出（带状态：待审阅 / 已发布 vN）。
  - 操作：查看、立即运行（历史中为“再次运行”）。
- **新建任务**（右侧抽屉，保持简短）：
  0. **所属**：在团队或项目中新建时就是这个层级，不显示；只有从“知识能力”新建时才需要选择团队或一个项目。来源、会话只能从这一层级中选，产物也归这一层级。
  1. **能力**：下拉，按分类分组。从能力卡片进入时已选好。
  2. **来源**：
     - 代码仓、文档集用下拉选择。
     - PR 和会话点“选择…”，打开单独的选择弹窗；选完后回到表单，只显示摘要，例如“已选 5 个会话”。
     - 会话选择弹窗不分页，包含会话名称或 ID 搜索、成员筛选（团队级任务可以选所有项目的会话，另有项目筛选）、AI 筛选（一句话要求，由 iCode 筛选，结果上方有一句说明）、全选和部分勾选。
  3. **方式**：能力声明了更新、并且这个输入已经有知识时才出现，“更新现有知识”（默认，下面一行写明上次以来的变化）或“重新构建”。来源没有变化时选“更新”，提示“来源没有变化，无需更新”，不能创建。
  4. **时间**：立即执行、指定时间、每天定时。每天定时显示“来源没有变化时跳过”，默认勾选。轨迹分析的每天定时改为“每天分析新共享的会话”。
  5. **高级设置**（折叠）：执行任务的智能体、提示词。
- **任务详情**：方式（例如“更新，10-18 09:30 版本 → 10-25 14:20 版本”）、步骤进度和日志。日志参照真实引擎的输出：CodeGraph 的 init / sync 与校验；开发范式挖掘的 prepare_input、读取 PR 和代码、写 analyzer.md 与 summary.md、archive_spec。完成后列出生成或更新的产物，提供“去审阅”。
- **产物与版本**：
  - 同一能力加同一来源重新运行，产生的是原产物的新版本，进入待审阅。同一个产物在待审阅里只保留一份草稿，再次运行时更新这份草稿（系统规则，页面上不展示）。
  - 索引类产物（CodeGraph、文档 RAG 检索）只有首次构建需要审阅发布（选择交付方式和适用智能体）。之后的每次更新或重新构建都自动发布新版本，更新说明自动生成，例如“同步代码变化：3 个新提交”；更新时来源没有变化，就保持当前版本。开发者端的索引通过在线查询使用，始终是最新版本，不出现“有更新”。
  - 每个产物记录构建基线：文档集记版本，代码仓记提交。下次更新时与当前状态比较得出变化。
  - 输入不同时生成新产物，名称带上输入，例如“开发范式 · PR #64”。
  - Mock 内容跟着输入变：标题、摘要、会话数或 PR 数与所选输入一致；轨迹诊断使用预置的真实报告（`content/trajectory/<主题>/`，由 `tools/import-trajectory.mjs` 导入）。

### 4.5 产物管理
- **列表**：只列出当前层级的产物，分为待审阅和已发布。
  - 卡片字段：名称、能力、状态（待审阅 / 已发布 v2 / 已发布 v2，新版本待审阅）。
  - 操作：审阅。
  - 已发布产物的来源在构建后有变化、且能力支持更新时，卡片上显示“提取后文档有变化：10-12 10:00 版本 → 10-22 16:40 版本，新增 1、修改 1”和“重新提取”。点“重新提取”打开新建任务，能力、来源、提示词按原任务预填，方式默认“更新现有知识”，不直接运行。
- **轨迹诊断**单独一组，卡片状态为“待应用 / 建议已处理”，有待应用的建议时显示“N 条优化建议待应用”（样式与“提取后文档有变化”一致），操作“查看建议”。项目卡片和“产物管理”页签上的数量也计入待应用的建议。
- **审阅工作台**（整页，知识类产物）：
  - 初版不提供修订（不做“和 iCode 对话”和手动编辑），产物原样展示，确认后发布。
  - **顶部**：产物名、状态、“发布”按钮。
  - **左侧**：文件列表。开发范式按范式分组，每组下是“范式总结”“代码分析报告”和各个 PR。
  - **中间**：内容；已发布产物的新版本可以切换到“与线上版本对比”。
  - **右侧**：生成时间、这一版基于哪个文档版本或提交、线上版本。
  - 索引类产物只有首次构建会进入待审阅，之后自动发布。已发布列表中显示“自动发布于 …”。
- **诊断工作台**（整页，会话轨迹诊断）：诊断不走审阅发布，也不出现在开发者端。
  - **左侧**：诊断报告、优化建议（每条带状态：待应用 / 已应用 / 不采纳）。
  - **中间**：诊断报告（报告自带的单文件 HTML）；或一条建议：类型、优先级、背景 / 现象 / 目标、修改内容（Skill 建议显示各文件修改前后对比；工具调用和任务指令建议显示写入 AGENTS.md 的规则，报告中的原始建议和配套代码修改折叠展示）、风险、验证方法。
  - **右侧**：应用到哪里，以及“应用优化”“暂不采纳”。应用前弹出确认，建议原样应用，不在这里修改：
    - **Skill 建议**：写成项目 Skill 的新版本（例如 arch-adr-writing 1.0.0 → 1.1.0），写入共享目录。iCode Teams 的“项目可用 Skill”显示新版本；成员冻结上下文之前使用新版本，已冻结的上下文不变。Talents 来源中的项目 Skill 也显示“Talents 改进”。
    - **工具调用、任务指令建议**：加入项目的“AGENTS.md 规则”，每加一条发布一个新版本。开发者端“项目知识”的轨迹分析中显示“AGENTS.md 规则”，更新后写入本机代码仓 AGENTS.md 的 iCode Talents 区块。工具建议中对代码仓脚本的修改只展示，需在代码仓中提交。
    - **暂不采纳**：可以填写原因，之后可以“重新考虑”。
- **发布**（弹窗）：
  - **发布到**：产物所属的团队或项目，不用选择。团队知识在每个项目中都可用。
  - **适用智能体**：全部智能体，或指定智能体（例如编码规范只给 Code Agent 和代码评审助手）。索引默认只给 Code Agent；再次发布时沿用上一版的选择。开发者一键应用时，默认应用到这些智能体。
  - **交付方式**：按知识类型预选，可以修改。“同步到本地”适合小而常用的知识；“云端查询”适合大而常变的知识。
  - **更新说明**：一句话写这次改了什么，开发者更新时会看到。

## 5. 开发者端页面

导航：项目知识、本地索引。

### 5.1 项目知识
- **项目切换**：只列出已加入的项目。
- **分组**：先是“团队知识”（全团队通用，在每个项目中都可用），然后是本项目的知识，按能力分类分组。
- **知识卡片**：名称、一句话说明、状态（未应用 / 已应用 / 有更新）；管理员指定了适用智能体时，显示“适用：Code Agent、代码评审助手”。不显示来源、任务、版本号等管理信息。
- **操作**：
  - **预览**。
  - **应用**：一键生效，不弹窗。管理员指定了适用智能体时，默认应用到这些智能体；否则默认是本机的本项目代码仓，本机找不到这个项目的代码仓时（团队知识也是这样），退回“所有智能体”。卡片菜单中可以“修改范围”（本项目代码仓 / 所有智能体 / 指定智能体）和“撤销”。
  - **更新**：有新版本时显示管理员写的更新说明，一键更新。
  - **全部应用**、**全部更新**。
- **结果提示**：应用后显示“已应用，范围：card-core-java”，并可展开“查看具体改动”。

## 6. 应用到 iCode 时写什么（页面上只在“查看具体改动”中出现）

- **同步到本地**：
  - 知识文件放在 `~/.icode-talents/knowledge/<项目>/`（不提交进代码仓）。
  - 安装对应的 Skill。
  - 在记忆中写一行知识索引：名称、位置、什么时候用、用哪个 Skill 查。
- **云端查询**：
  - 每个智能体只需添加一次“Talents 团队知识”MCP（写入智能体 yaml 的 `tools.mcp`）。
  - Skill 中说明调用哪个查询工具。
  - 记忆中同样写一行知识索引。
- **开发范式**：应用到本项目代码仓时，范式库放在 `<repo>/.icode-knowledge/miner/`，与引擎声明的产物位置一致；配套 Skill 为 `find-reference-spec`。
- **范围**：
  - **本项目代码仓**：Skill 写到 `<repo>/.agents/skills/`，知识索引写入 `<repo>/AGENTS.md` 的 iCode Talents 区块。
  - **所有智能体**：Skill 写到 `~/.chrys/skills/` 或 `~/.agents/skills/`。
  - **指定智能体**：写入 `~/.chrys/agents/<智能体>.yaml` 的 `skills.paths`、`memory.files`、`tools.mcp`。
- **AGENTS.md 规则**：应用到本项目代码仓时写入 `<repo>/AGENTS.md` 的 iCode Talents 区块；应用到指定智能体时写入记忆文件。Skill 的改进不在开发者端应用，由管理员写成项目 Skill 的新版本。
