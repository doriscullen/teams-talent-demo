## 1. 背景与目标

### 1.1 背景

客户在账单日或大额消费后希望将欠款分摊到多个月。当前 CardDemo 只有全额还款与账单支付，没有分期产品。本期在白金卡/金卡客户中试点 3/6/12 期，沉淀「分期计划—还款计划—提前结清」能力。

### 1.2 目标（原文量化指标，沿用）

| 目标 | 指标 | 本轮可否验证 |
|------|------|--------------|
| 提升分期渗透率 | 白金/金卡客户 8% → 15%（上线 90 天） | 否（业务指标，非本次本地验证范围） |
| 增加中间业务收入 | 手续费收入月增 12% | 否（同上） |
| 缩短申请路径 | 申请到建计划 p95 < 3s | 是（本地 Compose 计时） |

### 1.3 术语（沿用原文 §1.3，术语一致性按 `bank-domain-payments` 约束）

单笔消费分期 / 账单分期 / 手续费率（月费率，按**期初剩余本金**逐期计收）/ 尾差（末期吸收）/ 去重键（`idempotencyKey`）/ 提前结清。禁用「转帐」「划账」「手续费总额固定」等漂移表述；「清算 ≠ 结算」不混用。

## 2. 角色与权限

| 角色 | 职责 | 原文权限点 | 基线现状 | 本轮要求 |
|------|------|-----------|----------|----------|
| 持卡人 | 发起分期、查看本人计划、提前结清 | `installment:create`、`installment:read:self`、`installment:settle:self` | 基线 IAM 仅 `userType` = `A`/`U`，无权限点模型 | 映射 `U`；必须校验账户归属，越权 404 |
| 客服/运营 | 查询、**按授权协助办理写操作**（协助结清） | `installment:read:any`、`installment:settle:assist` | 同上 | 映射 `A` 中**可写**子角色：允许协助结清等授权写操作，写操作必留审计 actor |
| 风控/合规 | 只读规则与额度占用 | `installment:read:any`、`installment:rule:read` | 同上 | 映射 `A` 中**只读**子角色：**任何写接口必须被拒绝**（403 `FORBIDDEN`），不得仅凭 `userType=A` 放行写操作 |

- **不得压平为 A/U 二元判断**：`userType=A` 只是后台大类，客服（可协助写）与风控/合规（严格只读）必须在服务端具备**可执行的权限区分**（例如显式权限点或后台子角色），由**真实 token** 调用证明：客服 token 协助结清成功且审计 actor 正确；风控 token 调用任一分期写接口被拒。
- 具体映射表（账号、权限点、接口、期望结果）由 **design** 细化并落 `docs/design/05-api-catalog.md`；本轮测试映射**不冒充**正式 RBAC 确认，也**不扩大**为全平台认证改造（网关/JWT 属 §12-7）。
- 不得用同一账号轮换身份冒充职责分离（SoD）；正式权限模型列入 §12-8。

## 5. 业务规则

### 5.1 原文规则（保留，编号不变）

| 编号 | 规则 | 来源 | 优先级 |
|------|------|------|--------|
| BR-INS-01 | 单笔消费分期 ≥ 100.00；账单分期 ≥ 500.00 | 模拟业务确认 | 必须 |
| BR-INS-02 | 期数仅 3/6/12；月费率 0.60%/0.55%/0.50% | 模拟定价 | 必须 |
| BR-INS-03 | 每期本金 = 本金/期数（末期吸收尾差）；手续费按期初剩余本金 × 月费率，HALF_UP 2 位 | 模拟定价 | 必须 |
| BR-INS-04 | 同一交易/同一账单本金只能成功分期一次；去重键唯一 | 模拟业务确认 | 必须 |
| BR-INS-05 | 分期占用 = 剩余本金；提前结清释放 | 模拟业务确认 | 必须 |
| BR-INS-06 | 已逾期、已争议、已分期的交易不可分期 | 模拟风险政策 | 必须 |
| BR-INS-07 | 提前结清收剩余本金 1% 违约金，已收手续费不退 | 模拟定价 | 应该 |
| BR-INS-08 | 计划创建后 T+1 生效，首期计入下一账单 | 模拟业务确认 | 必须 |

### 5.2 本轮口径补充（标注来源，不与原文混同）

| 编号 | 规则 | 来源 |
|------|------|------|
| BR-INS-03R | 计费公式：`fee_k = HALF_UP(r_{k-1} × monthlyFeeRate, 2)`，`r_0 = principal`，`r_k = r_{k-1} − principal_k`；`principal_k = FLOOR(principal/term, 2)`（k < term），`principal_term = principal − Σprincipal_k`；`totalFee = Σfee_k`；`firstPeriodTotal = principal_1 + fee_1` | test-profile-v2（D-01/D-02） |
| BR-INS-09 | **本金级去重**：同一笔本金不得重复转分期。TRANSACTION 与 BILL 之间必须通过真实账单—交易来源关联比对「已关联本金 / 未关联本金」，既防「已单笔分期后又计入账单分期」，也防「已账单分期后该交易再次单笔分期」；不得扩为「账单存在任一分期即永久禁止该账单所有无重叠交易」。并发申请同一本金最多一个成功（另一个 409 `ALREADY_INSTALLED`） | test-profile-v2（D-09） |
| BR-INS-10 | **占用与释放**：建计划时本金已计入 `current_balance`，**不再从授权可用额度二次扣除**；`installment_occupied` = ACTIVE 计划剩余本金合计（视图展示口径）。还款按实际归还本金减少 `remaining_principal` 并同步减少 `current_balance`；结清使本金归零并只减少 `current_balance` 一次。禁止「清零展示字段即视为释放」、禁止「减 `current_balance` 后再额外释放同一笔授权额度」、禁止重复释放（double release）；手续费/违约金按实际账务单独过账；跨服务幂等与失败一致性必须保留 | test-profile-v2（D-07）+ v1.1 澄清 |
| BR-INS-11 | 单账户 **ACTIVE 分期上限 20 笔**（只计 ACTIVE）；第 21 笔拒绝；19 笔时两个并发申请最多一个成功。超限返回 `INSTALLMENT_LIMIT_EXCEEDED`（409，见 §7，PRD 补充错误码） | 本轮批准 + PRD 补充 |
| BR-INS-12 | 提前结清：`penaltyFee = HALF_UP(remainingPrincipal × 1%, 2)`；`feeRebate` 默认 0.00；`settlementTotal = remainingPrincipal + penaltyFee − feeRebate`；已收手续费不退 | 原文 BR-INS-07 + v2（D-08） |
| BR-INS-13 | 所有分期接口校验 IAM HMAC token：缺失/非法/过期 → 401；持卡人只能操作本人账户；后台接口仅 `A` 且须区分客服（可写）与风控/合规（只读）；越权读取一律 404，不泄露存在性 | v2（D-04）+ 原文 §6.2 + v1.1 PRD-004 |
| BR-INS-14 | 试算令牌 30 分钟有效。**创建**：`idempotencyKey` 30 分钟窗口内重复提交返回首次结果（HTTP 200），命中重放时不再要求 `previewToken` 仍在有效期；窗口外语义见 §12-6。**结清**：同一 `settlementIdempotencyKey` 重复请求返回 **HTTP 200 + 首次结清结果**，不重复扣款、不再生成分录、不重复释放；使用**不同新 key** 对已 `SETTLED` 计划请求 → **409 `SETTLEMENT_NOT_ALLOWED`**，同样不产生资金/分录变更 | 原文 §4.2/§6.2 + v1.1 PRD-003 |
| BR-INS-15 | **准入校验只含**：来源明确（交易/账单归属当前客户、状态可分期）、可分期本金余额、单账户 ACTIVE 20 笔上限、本金不重复占用（BR-INS-09）。**不得新增**「账户可用额度 ≥ 分期本金」一类准入门槛；已入账本金转入分期不再次扣减授权可用额度（BR-INS-10） | 用户本轮明确（PRD-001） |

## 7. 异常与错误码矩阵

| 错误码 | HTTP | 触发 | 用户提示（沿用原文） | 来源 |
|--------|------|------|----------------------|------|
| `INSTALLMENT_NOT_ELIGIBLE` | 409 | 金额不足、状态不支持、已逾期/争议中 | 按场景区分（原文 §4.2） | 原文 |
| `ALREADY_INSTALLED` | 409 | 本金已存在生效计划 / 并发同本金 | 「该交易已分期，请查看分期计划」 | 原文 + BR-INS-09 |
| `INVALID_TERM` | 409 | 期数不在 3/6/12 | 「仅支持 3 期、6 期、12 期」 | 原文 |
| `PREVIEW_EXPIRED` | 409 | 令牌过期或金额/期数不一致（同键重放不适用） | 「试算结果已变化，请重新试算」 | 原文 |
| `PRINCIPAL_EXCEEDS_LIMIT` | 409 | 本金 > 可分期本金余额 | 「最大可分期金额为 X 元」 | 原文 |
| `SETTLEMENT_NOT_ALLOWED` | 409 | 计划非 ACTIVE **且非同一 settlementIdempotencyKey 重放** | 「该计划已结清，无需重复操作」 | 原文 + BR-INS-14 |
| `AGREEMENT_REQUIRED` | 400 | 未勾选协议 | 「请先阅读并同意分期协议」 | 原文 |
| `INVALID_PARAMETER` | 400 | 分页/枚举/类型非法 | 「分页参数不合法」等 | 原文 |
| `INSTALLMENT_NOT_FOUND` | 404 | 不存在或越权 | 「未找到分期计划」 | 原文 |
| `CONCURRENT_MODIFICATION` | 409 | 乐观锁/并发改状态 | 「计划状态已变化，请刷新后重试」 | 原文 |
| `DOWNSTREAM_UNAVAILABLE` | 503 | account/ledger/billing 真实失败或超时 | 「提交失败，本次未产生分期，请重试」 | 原文 |
| `UNAUTHENTICATED` | 401 | 无 token / 签名或过期非法 | 「请先登录」 | PRD 补充（v2 D-04） |
| `FORBIDDEN` | 403 | 非 `A` 访问后台接口；或风控/合规只读子角色请求写接口 | 「无权访问」 | PRD 补充（v1.1 PRD-004） |
| `INSTALLMENT_LIMIT_EXCEEDED` | 409 | ACTIVE 计划数 ≥ 20 | 「已达单账户分期笔数上限」 | PRD 补充（BR-INS-11） |

- 幂等命中不返回错误（HTTP 200 + 首次结果），且不得产生第二组分录；结清同键重放同样 200。
- 通知失败不回滚主流程（记录待补发）；ledger 失败回滚计划与还款计划且不释放额度（原文 §4.2/§11.1）。
- 401/403 为基线约定（`docs/design/07-java-conventions.md` §4 仅含 404/409/400/503）的扩展，需同步落 API 目录。

## 8. 数据需求

表结构与字段沿用原文 §8.1（`installment_plan`、`installment_schedule`、视图字段 `installment_occupied`），本轮补充约束：

| 项 | 要求 |
|----|------|
| 去重 | 计划表 `idempotency_key` 唯一；结清另存 `settlement_idempotency_key`（唯一），用于同键重放判定；本金级去重需可查询「本金—计划」关联（用于 BILL/TRANSACTION 交叉核对与并发判定），不得只靠 `source_id` 唯一约束 |
| 金额 | 全部 `numeric(12,2)` / `BigDecimal`；禁止浮点；Σ`principal_due` = `principal`，Σ`total_due` = `principal` + `total_fee` |
| 额度 | `installment_occupied` = ACTIVE 计划剩余本金合计（展示/查询口径）；`current_balance` 只由 account-service 变更；结清只减一次 |
| 审计 | 创建、结清、后台查询/导出写审计：actor、action、resource、payload、时间；留存 3 年 |
| 留存 | 计划与还款计划 5 年（模拟制度）；去重键同期保留 |
| 脱敏 | 响应与日志卡号仅后 4 位；客户姓名「姓 + \*」；响应不返回完整卡号 |
| 时间 | 时区 `Asia/Shanghai`；「近 6 个月」按日历月、跨月取目标月末；测试显式记录时钟与时区，不用 180 天替代 |

## 14. 领域约束（按 `bank-domain-payments` L3）

- 业务规则编号：BR-INS-01..08（原文）+ BR-INS-03R、BR-INS-09..15（本轮补充，来源逐一标注）。
- 监管/制度引用（模拟，沿用原文 §13）：《商业银行信用卡业务监督管理办法》信息披露与费率明示；行内分期业务管理办法（模拟编号 `INST-POLICY-2026`）。本文件为演示材料，不构成合规结论。
- **准入校验范围（v1.1 修订）**：仅校验 ① 来源明确（交易/账单归属与可分期状态）② 可分期本金余额 ③ 单账户 ACTIVE 20 笔上限 ④ 本金不重复占用/不双扣（BR-INS-09/10）。**不设**「账户可用额度 ≥ 分期本金」门槛，也**不**规定跨维度的固定校验次序。边界用例：99.99/100.00；499.99/500.00；19/20/21 笔。
- 占用与释放：本金已计入 `current_balance`，不二次扣减授权可用额度；还款/结清按实际偿还本金只释放一次，禁止 double release。
- 状态机：`installment_plan` `ACTIVE → SETTLED`（结清）、`ACTIVE → CANCELLED`（取消）；`installment_schedule` `PENDING → PAID`；禁止跳态与直接改状态字段。
- SoD：定价配置由定价岗维护；计划只能由客户或客服发起；风控/合规只读（写请求必须 403）。
