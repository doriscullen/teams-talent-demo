# arch-adr-writing 技能

## 概述

本技能用于按标准格式记录架构决策，确保决策可追溯。
写作前先对齐本技能 `scripts/adr_lint.py` 的必需章节命名，避免「内容齐备但结构校验不通过」的返工；
定稿前以 lint 退出码 0 作为结构门禁的通过条件，内容质量仍由人工评审把关。

## 工作流

1. 识别需要ADR的决策点
2. 写作前对齐章节命名契约（见「章节命名契约」）：`背景 / 决策 / 备选方案（或候选方案）/ 后果 / 状态`，后果章节标题统一写作 `## 后果（影响与回退路径）`
3. 按模板编写ADR：背景/问题/决策/备选方案/后果
4. 引用相关设计文档与评审记录
5. 编号归档（ADR-NNN）
6. 关联到设计文档
7. 定稿前运行 `python scripts/adr_lint.py <adr.md>`：退出码 0 且 `missing` 为空方可提交评审；不通过时按「校验失败处理」修正后重跑

## 章节命名契约（与 adr_lint.py 对齐）

| adr_lint.py 必需项 | 推荐写法 | 说明 |
|------|------|------|
| 背景 | 标题 `## 背景` | 问题、约束、影响范围 |
| 决策 | 标题 `## 决策` | 选定方案与落地约束 |
| 后果 | 标题 `## 后果（影响与回退路径）` | 统一以「后果」开头，同时保留「影响与回退路径」的 L3 语义 |
| 状态 | 标题 `## 状态`，或元数据表的 `| 状态 | 已接受 |` 行 | 两种写法均满足校验 |
| 备选方案 / 候选方案 | 标题 `## 备选方案`（或 `## 候选方案`） | 二者任一出现即视为满足 |

- 命名规范属于**写作规范**，目的是索引、检索与评审口径一致；同一 ADR 内部保持一致。
- 校验器的**实际能力**：`adr_lint.py` 用 `REQUIRED` 列表对整份文本做子串判断（`if k not in text`），
  **不做标题解析**。因此正文任意位置出现同名词也会通过；反过来说，「lint 通过」只证明必需关键词命中，
  **不证明章节齐备或内容完整**。
- 不得为通过校验只改标题而不动内容：若原有「影响与回退路径」章节已写明影响与回退，改标题即可；
  若原本就没有后果内容，必须补写内容，而不是仅靠标题凑词。
- `adr_lint.py` **不检查**：备选是否≥2、量化权衡表是否完整、是否关联设计文档与证据、内容是否实质充分。
  这些只能由质量门禁与评审确认。

## 深度档位（L3 实施级）

| 档位 | 要求 |
|------|------|
| L1 | 骨架要点，用于讨论 |
| L2 | 标准评审级（银行生产默认） |
| L3 | 在L2基础上增加以下深度内容（高风险/监管/复杂集成时必用） |

### L3 工作流补充

- L3 ADR增加量化权衡表：成本/性能/运维/审计/风险五维对比
- 记录决策影响与回退路径
- L3 的「后果（影响与回退路径）」须逐项给出影响对象、量化范围（金额/笔数/时长等可核对的量），
  以及回退触发条件与回退步骤；lint 不校验这些内容，属评审必查项

### L3 质量门禁

- [ ] 备选≥2
- [ ] 量化权衡表完整
- [ ] ADR关联设计文档与证据
- [ ] `adr_lint.py` 退出码 0 且 `missing` 为空（命名契约通过）
- [ ] 后果章节给出影响对象、量化范围、回退触发条件与回退步骤

> 主模板含【L3必填】深度字段：`templates/adr-template.md`；详细档位定义见《Skill深度分级规范》。

## 校验与失败处理

### 执行

```bash
python scripts/adr_lint.py <adr.md>          # 人读输出
python scripts/adr_lint.py <adr.md> --json   # 取 missing 清单
```

### 退出码语义

| 退出码 | 含义 | 处理 |
|------|------|------|
| 0 | `missing` 为空，必需关键词全部命中 | 通过，进入评审 |
| 2 | `missing` 非空，列出缺失的关键词 | 逐项核对后修正并重跑 |
| 3 | 文件不可读（`OSError`：路径错误、权限不足等） | 修正路径或权限后重跑，不算内容缺失 |

补充：脚本以 UTF-8 读取文件，编码错误会抛 `UnicodeDecodeError`（不是 `OSError`），
不会返回退出码 3；遇到时应先确认文件编码，不要据此判定章节缺失。

### 校验失败处理（限次）

1. 读取 `missing` 清单，逐项判定属于「命名不符」还是「内容缺失」。
2. 命名不符 → 改标题并保留正文；内容缺失 → 补写对应章节（背景/决策/备选/后果），不得仅堆砌同义词。
3. 修正后重跑，**同一 ADR 最多重跑 2 次**。
4. 仍为退出码 2 且 `missing` 未减少时，停止自动修改；记录 ADR 编号、`missing` 清单、已尝试的修改与判断结论，
   提交架构负责人确认命名口径或补齐内容。
5. 不得为了通过校验删除实质内容、改写决策语义或删除整个章节。
6. 仅读取、运行 lint 与诊断可自动推进；对已归档/已接受 ADR 的正文改写属于内容变更，须在任务授权范围内执行，
   超出授权时只提交修改建议。

## 质量门禁

- [ ] 背景-决策-备选-后果四要素齐备
- [ ] 章节标题符合命名契约（后果章节含「后果」字样）
- [ ] `adr_lint.py` 退出码 0 且 `missing` 为空
- [ ] 修改模板或 `adr_lint.py` 任一方后，用模板生成一份样例 ADR 运行 lint，确认两者章节契约仍一致
- [ ] 每个决策有理由
- [ ] 关联设计文档

## 常见失败模式

| 失败模式 | 表现 | 规避措施 | 重试策略 |
|---------|---------|---------|---------|
| 章节命名与校验器不一致 | 内容齐备但 `missing=["后果"]`、退出码 2 | 写作前对齐命名契约；后果章节统一写作 `## 后果（影响与回退路径）` | 改标题后重跑 lint，最多 2 次 |
| 只改标题不补内容 | lint 通过但后果章节无影响/回退实质内容 | 命名修改与内容补齐分开判定（见校验失败处理第 2 步） | 补齐内容后提交评审 |
| 误判校验通过的含义 | 把 lint 退出码 0 当作 ADR 完整合规 | 明确 lint 仅做关键词子串判定；备选≥2、权衡表、设计文档关联由评审确认 | 按质量门禁补检后重审 |
| ADR遗漏 | 决策点未被记录 | 决策点自动识别提醒 | 补录 ADR 后重跑 lint |
| 内容空洞 | 模板字段有标题无实质内容 | 模板强制字段校验 + 评审核对后果与理由 | 补全实质内容后重审 |
| 反复修改仍不通过 | 多次重跑 `missing` 无变化 | 达重试上限即停止，记录清单与判断并升级架构负责人 | 人工确认命名口径或补齐内容后重跑 |
